# Bug audit trail: which test catches which defect

This is the test-side half of the original bug register.  The library-side half (defects and inherited behaviour of the original, candidate defects)
is `docs/bugs.md` in the `dsplib` repository.  What is kept here: how each defect found since the rows began to be tested against something other
than their own chunk test was caught (sections A, B), the tests added to harden that (D), what the harnesses do NOT compare (E), how a "fail before" was
demonstrated (F), the x86-64 findings of the switch-over and of the static layout comparison (T, U), and the table of defects that were found AND FIXED
(`Resolved`, ids VR1 ..), each with the job that proves the fix.  Section letters are those of the original register; the sections that moved to
`dsplib` (C, G .. S, V) are absent here.  References to `NOTES.md`, `docs/porting-journal.md` and to pass names (RS1, PM3, CM2, X64FIX ...) are to the
porting project's history, which lives in the blob-tools repository (`docs/porting-journal.md`).

**Classes.**  `dead-output` = the port treated a value as unused / unneeded and the original consumes it; `state-not-exercised` = the code path exists in the
original but no scenario reached it; `uninit-heap` = a field the original writes was left to malloc() (zero in every test process, garbage in a live one);
`aliasing-UB` = C undefined behaviour that only some optimisation levels turn into wrong code; `name-collision` = a port data symbol replaced a different
symbol of the original of the same name or shape; `wiring` = arguments / buffers / return values connected wrongly (decompiler artefacts included);
`harness-gap` = the harness could not see the difference (the fix is then a harness change); `transcription` = a width / sign / offset slip when
hand-cleaning the decompile.

## E. Output coverage (what the differential harnesses do NOT compare)

Audited by reading the plain-C phase-1 harnesses and the shared harness library; the 60 C++/V/Z row harnesses compare whole objects, recorder traces and a patterned heap with red zones (`test/harness`), the V.34 tiers hash a whole fake object.  Gaps found:
* rd, b103, v23: only API outputs (events / counts / audio checksums); object state was not compared at all.  Now compared at `B103FP_delete` / `V23` free time by `h01_heap` (this is how H01-1..3 were found); *per-call* state is still not compared.
* `LocLoop` (cfg[0]==2) is not testable: the blob crashes on the first call.
* v32 family harnesses assume a zero heap (the blob itself segfaults in `v32_org` under a 0xa5 heap), so `h01_heap` omits `v32_org` and `n01_v32status`.
* Debug text was compared only in `v8_fsm`; now also in the V.8 lifecycle test and the AGC block; still not compared for the functions listed in section C.
* Static LOCAL buffers of the blob (`tx_in_internal`, `rx_out_internal` in `V32FP_modem`) are invisible to the harnesses.
* Return-value upper bits (functions returning `short`/`char`) are compared only as far as the harness prototype reads them.

## T. X3 (switch-over): findings in the port and in slmodemd (x86-64)
- FIXED: the V.34 module object had two layouts at -m64 (C V34Obj of src/v34/v34_object_view.h vs C++ tagV34Object of src/v34/v34_object.h; 199 of 229 common members differed): VPcmV34Create crashed in the first live V.34 call on x86-64.  V34_PAD64 in the class + pad64 in the harness mirror + test/x3_v34layout.py.  Raw `unkXXXX_ + K` offsets that cross a widened pointer slot: two sites in src/v34/handshake/v34_hs_rx_receive.cpp (fixed); the other V.34 C++ files were grep-audited, none left.
- FIXED (X64FIX, `bugs.md` VR6): src/vpcm/dp_vpcm.cpp vpcm_delete wrote `pair[1] = regWord_` through int32_t *: struct dsp_info has `long clock_deviation` at +8 on x86-64, so the clock deviation was not updated there.  The z01 golden was not the cause: the harness model was.
- CANDIDATE (not changed): src/v32/v32_equalizer.c reads `void *` from 4-byte aligned addresses (UBSan, x86-64): works on x86, the pointers sit at i386 offsets inside raw blocks.
- CANDIDATE (not changed, blob hazard): V8Create does not clear the 36-short history that V8agc reads (p + 0x3e): a dirty heap changes the originate side's ANSAM detection (the "call start flake" of N02).
- CANDIDATE (not changed, slmodemd + blob): modem_main.c does FD_SET(dev->fd) with dev->fd == -1 after the child socket closes: _FORTIFY_SOURCE aborts the process ("buffer overflow detected") at the end of a call.
- slmodemd, tiny fixes: modem_debug.c pointer-to-int cast made explicit, modem_ec.c EC_DEBUG format arguments cast (int).
